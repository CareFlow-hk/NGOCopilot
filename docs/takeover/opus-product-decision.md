# 產品決策（第一輪）

## 一、拆分決定：兩個交付物

**決定：另建 `CareFlow Scheduler` 獨立 repo。NGOPilot 收窄為「文件工作流」產品。**

理由：
- **工作流不同。** 活動排程是結構化流程：小冊子 → 審核 → 月曆 → 選擇 → 衝突。它不需要 agent harness。放進 Pilot 會同時暴露 agent 設定，也會和既有的 cron「Scheduler」撞名。
- **可重用的程式很少。** 只有 PDF 讀取和模型呼叫能重用，不足以抵銷整合成本。
- **維護成本可控。** Scheduler 刻意做小：單一前端、輕量後端、單一使用者、不收集個人資料。
- **名稱必須分開。** 「社區活動選擇」對象是會員或家屬的活動時間表；「照顧員 Roster」對象是員工排班。兩者各自命名，不得互稱 Scheduler。Pilot 內的 cron 功能改名為「自動化」，並隱藏。

## 二、Scheduler 範圍

- **主要使用者：** 中心前線同工，在櫃檯協助長者或家屬揀活動。
- **第一個任務：** 揀 3–5 個活動，即時知道有沒有撞時間，然後列印。
- **導航（四頁）：** 匯入審核 ｜ 活動目錄（搜尋名稱／日期）｜ 月曆 ｜ 我的選擇。
- **首次使用：** 預載第 125 期已審核資料，頁面清楚標示「歷史樣本：2026 年 7–9 月」。另設「上載新小冊子」入口。
- **明確不做：** 網上報名、會員資料、姓名電話、付款、名額預留、通知、員工排班最佳化。

## 三、NGO 試用驗收合約

1. **抽取：** 84 頁全部跑過真實模型。每個活動附來源頁碼，並在旁邊顯示該頁影像。
2. **審核：**
   - 日期、星期、堂數互相矛盾的，標紅「待確認」，不自動修正。
   - 名額一律顯示「以中心為準」。
   - 審核者可標記「FULL」，因為印章只存在於頁面影像，文字層抽取不到。
   - 隱藏範本列要能刪除。
3. **日期循環：** 支援單次日期、每週範圍、跳過日期。展開後的所有日期必須可在月曆上逐一檢查。
4. **衝突：** 以確定性時間區間計算，說明「哪兩個活動、哪一天、重疊多少分鐘」。附單元測試。
5. **匯出：** 可列印時間表及 ICS，頁腳註明「規劃用途，非報名確認」。
6. **持久化與修正：** 修正後的資料重新整理不會遺失；保留原值與修正值。
7. **失敗恢復：** 單頁抽取失敗可重試，不影響其他頁；模型無法使用時，仍可用已審核資料完整操作。

## 四、Pilot 處置

- **只顯示四張工具卡：** 紙本表格、錄音筆記、政府表格、照顧員 Roster。
- **隱藏通用功能：** recipes、skills、apps、extensions、cron、模型設定全部收進管理員開關，不刪除。
- **介面語言：** 登入頁改為 zh-HK。
- **紙本表格自動核准必須撤回。** 預設改為人工確認；低信心欄位要高亮，確認後才能匯出。這是原本 Documents 產品的核心原則。
