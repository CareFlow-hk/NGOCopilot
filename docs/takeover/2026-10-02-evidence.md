## 當前程式事實

- NGOPilot 基線：`main`，`d935476`，接管開始時工作目錄乾淨。
- MCP 註冊表只有紙本表格、錄音紀錄、政府表格、照顧員排班四個工具。
- UI 中的 Scheduler 對應 Goose 的 cron／recipe 定時執行，不是活動冊月曆。需求原型借用了這個畫面，活動領域尚未實作。
- 接管基線的紙本表格自動核准提取值並匯出；原 CareFlow 與最新背景主張 AI 草稿應由人覆核。此差異已在本次交付修正。
- `deployment/frontend` 用瀏覽器適配層重用桌面 React renderer；`deployment/backend` 是 FastAPI／PostgreSQL／GCS gateway，每個使用者管理一個 ACP 程序。
- MCP 任務、CareFlow、Roster 和 Agent 各有持久化狀態。雲端 gateway 另有帳戶、會話與 GCS 快照，不能用單一資料庫描述整套產品。
- MCP 預設執行套件內 `payloads/` 的 CareFlow／Roster 副本，不等於旁邊 CareFlow repo 的最新程式。
- CareFlow 當前程式使用 FastAPI BackgroundTasks；README 中 Celery 等描述不能直接當作已實現的持久任務系統。
- 此處 Atlas 主 checkout 為 React／localStorage 的合成資料前端原型。其他歷史 checkout 的帳戶後端不能套用到這個目錄。

## 發現及修正

- 移除紙本 start/status 自動批准；公開 review 操作，匯出前至少一筆已明確確認。工作台額外要求審核人與來源核對勾選。沒有自動批准設定；完整 MCP 的 confirm_all 僅供使用者明確確認未修改資料，不由 start/status 呼叫。
- Secret literal／URL-encoded／Bearer 遮蔽用於 worker 例外與診斷；不宣稱是個資匿名化。
- 原生模組相對路徑寫入 tenant app-data；紙本 vision/text 的來源相對日誌改由自有 adapter 導向 app-data，避免下次 bootstrap 雜湊失敗。依賴原檔未修改。
- 舊前端跨目錄 SDK type resolution 修正，登錄介面繁體中文，hidden 樣式修正。
- Scheduler 星期與日期矛盾不能確認，與 Opus 最終 P0 一致；草稿不進目錄／個人時間表。預載樣本區分 20 已核對、5 草稿、1 取消。

## 限制與誠實證據

**NGO 實際採用／獨立可用性／省時評估：NOT_READY。** 尚未邀請或聯絡機構，無人工 gold label、無虛構用戶或改善百分比。沒有雲端部署、機構帳戶隔離實測或比賽提交。Atlas 仍是現有合成前端原型。

先前一次錄音驗收失敗是本機 TTS 產生零長度檔案；已重新產生有效 32.53 秒 WAV 並完成真實呼叫，失敗記錄保留。Word 中文初次在驗收 PDF 中空白是 renderer 未載 CJK 字型，載入系統字型後完整顯示；未修改資料來掩蓋問題。測試命令若覆寫 pytest addopts 必須保留 --import-mode=importlib，否則同名測試檔收集會碰撞。

正式服務前尚需依機構決定部署、資料處理安排、身分與保留政策。此交付先提供完成且可重現的本機有人陪同試用。
