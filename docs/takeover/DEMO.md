# LIGHT 演示與機構試用

## 兩分鐘演示

事先開啟 8310 Pilot、8311 Scheduler，以及既有 Atlas。不要拿真實服務對象資料公開演示。已運行的紙本與錄音結果來自實際模型；現場沿用既有結果時要說明不是即時生成。

- **0:00–0:15**：CareFlow 是面向 NGO 前線的工具集合。Pilot 整理文書，Scheduler 整理活動安排，Atlas 展示地區探訪與跟進。此次交付是本機試用版。
- **0:15–0:45**：Pilot 最近工作選「合成紙本 · 待審核示範」。左邊原圖，右邊欄位。指出模型把測試備註誤放健康關注；修正前不應採信。未勾來源確認會拒絕審核，未審核沒有匯出入口。由演示者親自核對、填自己的審核名稱、勾選後產生 Excel。
- **0:45–1:05**：開啟已完成的 32 秒合成會議。可播放原錄音，指出「房間預訂尚未確認」，展示 Word 五欄結果。檔案亦在 samples 中，避免現場網絡延遲。
- **1:05–1:45**：Scheduler 先指出歷史樣本標記。展示原頁、草稿及修訂；目錄選「模型場景大制作」與「晴天下的你我他（貧富宴）」。7 月 22 日重疊 120 分鐘；加入英國篇後共 3 活動、6 時段。展示時間表、ICS 及列印入口，說明並非報名確認。
- **1:45–2:00**：切 Atlas，明確說明是既有合成地區資料原型。收尾展示可追溯來源與人工覆核，而非宣稱已省時、已採用或已晉級。

排班阻塞例子只供內部查看，現有工作簿可能含機構個案資料，不放入公開演示或截圖。政府 PDF 作備用題材，說明範本版本與未知欄位留空。

## 向 NGO 驗證什麼

工程已通過不等於機構願意持續使用。建議第一次有人陪同試用只要求完成一項真實工作，先用公開活動冊或合成／經機構確認可處理的資料。

1. 同工用目前方式完成一份任務，記錄實際時間及困難。
2. 同工自行操作對應工具；開發者只記錄卡住的位置，不代替他確認。
3. 記錄完成率、需要幫忙次數、錯誤欄位、修正時間、輸出是否能接續原有工作。
4. 問「下星期哪件工作會再用它？」並記錄實際再次使用；訪談意願不當成採用。

空白記錄表：日期／角色／任務／資料同意範圍／原方式分鐘／工具分鐘（含核對）／錯誤及後果／是否獨立完成／是否願意再用及理由。尚未量測欄位維持空白，NGO 驗證狀態 **NOT_READY**。
