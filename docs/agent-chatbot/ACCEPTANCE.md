## 驗收中修正的實際故障

1. 政府表格模型回覆被截斷時，原生邏輯把空內容當空 JSON 成功；現在明確回報失敗，並給足抽取回覆預算。
2. 未提供 elder ID 的已核對政府表格不能匯出；適配層使用原生匿名檔名，保留資料缺失，沒有造身份資料。已核對失敗任務可重試匯出。
3. 樂悠咭舊模板把出生日期指到簽署日期；適配層修正三個欄位，初始簽署日期強制留空。舊測試任務保留並顯示警告，不把舊 PDF 当最終驗收成品。
4. macOS 直接檢查 Docker 掛載的運作中 SQLite 後出現 WAL I/O 錯誤；停止服務，在 Docker 內檢查八個資料庫皆完整並 checkpoint，重新啟動後主 Agent 全流程通過。交付說明要求運作中使用 API／容器內工具，備份先停止服務。

## 尚未覆蓋的環境

- ICS 已由標準解析器核對，尚未實際匯入使用者的 Apple／Google 日曆帳戶，因此 Opus 的外部日曆匯入驗收項尚未完成。沒有在使用者日曆寫入測試事件。
- 本輪是 macOS Docker Desktop 單一使用者的本機版本；沒有公網部署、GCS 生產端到端、多機構隔離、Linux 或真實 NGO 排班驗收。
- 排班底稿及所有本輪驗收輸入都是合成資料；工具保留舊流程的原生 Excel 格式要求。真實 NGO 試用前需配置該機構的人員、技能、固定安排與工作表。
- 未進行真實政府提交、活動報名、排班發佈或轉寫銷毀。
