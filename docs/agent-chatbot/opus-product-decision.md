# 产品决定（PM：Opus 5.5）

## 一、定位
**NGOPilot 是社工的 Agent 助手。** 社工在 Wilson 原有的聊天界面里，用一句话加附件交代工作。Agent 自己选工具、跑流程，需要时停下请人核对，最后把可下载的真实成品交回对话。

## 二、聊天首页与工具发现
- **首页就是 Wilson 原 Chatbot，作为唯一主入口。** 四卡工作台对用户下线，最多保留为内部调试路由，不做并列导航。
- **示例提问**：输入框上方放 4–5 个示例提问 chip，例如“把这几张纸质表格整理成 Excel”。点击只填入输入框，不直接启动工具，由 Agent 规划。
- **能力介绍**：用户问“你能做什么”时，Agent 按 MCP manifest 列出工具及各自所需附件。
- **附件**：附件直接拖进对话。Agent 根据意图和文件选工具。缺材料就具体追问，例如“还需要护送 Excel”。意图不明时先问，不猜着启动。

## 三、任务在对话内连贯运转
工具调用结果在消息流中渲染为**任务卡**，不跳转独立页面：
1. **启动**：start 后出卡片，显示工具名、输入文件和状态（排队/处理中/待核对/已完成/失败）。轮询 status 时原地更新同一张卡，不刷屏。
2. **待核对**：卡内展开审核表，逐项字段对照原始来源，可直接修改，底部有“确认无误”按钮。
   - Agent 可以总结“有 3 处低置信度请重点看”，也可按用户口头指令通过 review 修改字段。
   - **最终确认必须由人点按钮**，Agent 不得代确认。聊天路径不启用自动批准。
   - 审核内容太复杂时，可“在新窗口打开”，完成后回到对话。
3. **导出**：确认后 Agent 调 export，卡片出现下载按钮，显示文件名、格式和时间。
4. **失败**：如实显示错误和可行的下一步，禁止生成假结果或空文件。
5. **持久**：卡片按任务 id 持久化，刷新或重开会话后状态和下载仍在。

## 四、Scheduler：本轮接为第五工具，范围收窄，定为 P1
- **聊天内范围**：上传活动手册 PDF → 抽取活动列表 → 在任务卡里逐项审核 → 导出 ICS 和活动清单。
- **独立 UI 保留**：日历视图、选择和冲突处理留在 Scheduler 原 UI。任务卡提供“打开日历”链接，带同一任务 id。不在聊天里重做日历。
- **与 Roster 区分**：工具名叫“活动手册→日历”，Roster 叫“人手排班”。manifest 描述里写明两者差异，防止误路由。
- **数据**：演示用合成手册。真实 7–9 月手册只能称“历史样本”，Agent 不得说成当前可报名活动。
- **上线门槛**：P0 全部验收通过后才接入。10 月 6 日中午前未通过 P1 验收，演示就不出现 Scheduler，不带半成品上台。
- **工程约束**：按 AGENTS.md 做成独立 sibling 包，不改其他工具。

## 五、优先级与验收

**P0：老四工具，10 月 5 日晚前完成**
1. 打开即是原 Chatbot，四卡工作台不可见。
2. 四个工具各跑通一次端到端：自然语言加附件 → Agent 自选工具（不靠按钮硬编码）→ 进度 → 审核 → 确认 → 下载。下载文件能用 Excel/Word 打开，内容与输入一致。
3. **路由测试**：每个工具 3 种不同说法，12 条全部选对。1 条歧义请求，Agent 必须追问而不是乱选。
4. 未确认的任务无法导出，Agent 无法绕过审核。
5. 刷新页面后任务卡和下载仍可用。
6. **故障注入**：工具或模型报错时，卡片显示失败，对话不卡死，不产生伪造输出。
7. DeepSeek 加 Azure 或 DashScope，至少两套模型各跑通一轮，其中一套作演示备份。
8. 现有工具测试不修改即全部通过。

**P1：Scheduler，10 月 6 日**
1. 合成 PDF → 活动审核 → 导出的 ICS 能导入 Apple 或 Google 日历。
2. “打开日历”能看到同一批活动。
3. 说“排一下下周人手”时路由到 Roster，不会进 Scheduler。

**冻结（10 月 6 日晚）**
- 只修 bug，不加功能。
- 准备演示脚本（四个或五个任务按顺序）和一段离线录屏作为备份。

**本轮不做**：Atlas、其他新工具、工作台重做、专门开发多工具自动串联。用户一次提多件事时，Agent 逐个调用即可。

## 给 Codex 的约束
- 不重写 Agent。只做 MCP 接入、附件传递和任务卡渲染。
- 不碰 `algo-dependencies/`。
